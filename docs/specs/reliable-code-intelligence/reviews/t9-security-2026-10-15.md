## Resolved finding

**Medium — vector availability is conflated with embedding authority.** `core/integration/src/code_evidence/readiness.rs` requires a matching `code_vectors` index inside its unconditional embedding predicate. A valid source/local-embedding setup using only the lexical lane therefore reports `Unsupported` although the shared evidence operation can execute without a vector lane. Missing configured vector retrieval is also reported as unsupported embedding authority instead of degraded retrieval prerequisites. Separate actual local embedding/tokenizer/representation validation from per-enabled-lane vector presence and embedding-space compatibility; disabled vector must not affect evidence readiness. Add lexical-only/no-vector and enabled-vector-missing readiness regressions.

**Resolution re-reviewed:** local embedding asset/tokenizer/representation validity is now independent of vectors. Only an enabled Vector lane checks its handle and space; missing/incompatible enabled retrieval reports Degraded. The lexical-only/no-vector regression executes the actual shared operation and returns evidence while reporting Supported; enabling a missing vector changes readiness to Degraded.

The additional `RerankScorer::supports_code_input()` declaration defaults false. Actual constructed local ONNX scorers opt in; readiness, preflight and pre/post-score checks require it alongside locality and compatible identity. A local identity-only generic scorer no longer advertises code-input readiness. This narrows model exposure without changing generic reranking.

## Other reviewed boundaries

- Native evidence handles decode trusted `CodeSourceContext` once into private Rust state. Per-call input is strict `CodeEvidenceQuery`; query-side scope/requester/model/calibration fields cannot alter it.
- HTTP uses strict Zod input and only accepted query fields, with trusted startup source context. Stdio removes only `op` before strict Rust DTO decoding. Shared Rust admission still enforces UTF-8 byte limits before model work.
- Calibration paths are explicit trusted startup configuration, never query fields or discovered repository files. Recipes load the artifact once, before model construction. The 64-KiB bounded loader rejects nonregular/symlink inputs, uses Unix `O_NONBLOCK | O_NOFOLLOW`, verifies the opened descriptor and caps the actual read. Failure messages do not disclose file contents or paths. Malformed explicit selections fail instead of silently disappearing.
- Scorer readiness requires an actual local handle and compatible identity; calibration/corpus quality are not certified. HTTP without trusted source context suppresses evidence/source capability readiness.
- Native scorer feature propagation reaches the shared adapter implementation; transport wrappers do not duplicate ranking or policy behavior.
