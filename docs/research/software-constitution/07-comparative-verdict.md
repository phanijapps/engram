## Verdict: retain the guardrails, restore the argument

**Gained versus v0:** v2 standardizes frontmatter and direct-input fingerprints (v2-spec:1-15; v2-plan:1-14); aligns canonical requirements, acceptance, named gates, steps and tasks (v2-spec:35-59; v2-plan:23-35; v2-tasks:18-41); and replaces an expansive profile narrative with concise, inspectable work items. v0 already had evidence labels, owner authority, acceptance, and a verification stance (v0:34-41, 54-72, 95-121): these are not v2 inventions.

**Lost versus v0:** v0 states the causal chain, real harm, owner decision, and limits of the evidence up front (v0:46-52, 58-71, 76-87). The v2 spec supplies fragments and IDs but no comparable “why this, why now, what failure costs” (v2-spec:20-47). The specific homework regression is **field completion and duplicated cross-reference tables substituting for a concise, evidence-backed argument**: a reader must assemble intent, evidence, requirement, acceptance and gate across sections and artifacts, while `total` can be asserted mechanically (v2-tasks:29-34). This is not an argument for returning to v0's ledger/hash repetition or treating all tables as bad.

## Merge criteria for a redesign

The following are acceptance criteria for the proposed redesign, not claims about today's gates. Require an actual fixture suite and human review; do not call a document valid merely because a regex passes.

1. **60-second argument.** Each spec begins with a compact problem → consequence → desired outcome summary, with source links and explicit uncertainty where load-bearing. A reviewer can locate the change, failure cost, scope and proof route in the opening screen. Test with a timed staff-review exercise on both the 002-style complex and 011-style small cases; record whether each item was found, not merely word count.
2. **Single canonical behavior.** Each behavior has a stable REQ ID, priority and observable trigger/response; acceptance states expected success and relevant denial/failure. Each REQ maps to at least one AC and executable gate/fixture, including negative cases where meaningful. No second table may silently redefine behavior. A no-negative-case claim needs a reason; human review judges adequacy.
3. **Authority and evidence.** Preserve the owner decision/ledger dispositions and out-of-scope boundaries, including deferred item, owner and trigger when applicable. Every consequential claim has a resolvable, revision-pinned source or an explicit assumed/likely label and risk. Test a stale/missing source and an unresolved owner decision; neither may be presented as proven or silently ratified. Human reviewers verify fidelity, not mere LED string presence.
4. **Trace without transcription.** Preserve discoverable REQ→AC→gate and REQ→step→task coverage, including an explicit exception with owner and trigger where not covered. Allow one compact mapping, structured links or generated views instead of a mandatory duplicated REQ × task matrix. Test both valid compact and valid tabular fixtures, a missing mapping and a dangling ID. Guard against incidental ID mentions and duplicate definitions; report exactly what is absent.
5. **Honest verification.** Gate entries name runnable commands or fixtures, expected observable results, and actual evidence/status; `NOT_RUN` is not PASS. Claims must not exceed the test's demonstrated scope. Mutation fixtures with a missing path, present clean path and present violation must detect the appropriate outcomes. Any omitted check states reason, owner and revisit trigger.
6. **Preserve controller invariants.** Valid redesigned artifacts pass `validate_artifact` with required frontmatter, job/cycle/type/role/profile/snapshot, timezone, ready status, placeholder handling, and hash-checked direct inputs. Tests reject stale, missing, duplicate, self and escaping references, incorrect identity or snapshot, and unresolved supported placeholders. Preserve accepted-evidence integrity and existing stage, review and ratification ordering; do not weaken them to save prose.
7. **Enforcement, not appearance.** Keep canonical artifact/layout policy, stub rejection at the appropriate lifecycle stage, referential integrity, requirement coverage, and ratification-before-build protection. Preserve existing `--strict` behavior and explicitly document any changed rollout/advisory policy. Replace the current conditional string-presence checks with checks of defined IDs and real links, including absent upstream sets; test negative and positive fixtures. Do not assert that today's checker already provides this stronger guarantee.
8. **Loosen presentation only.** There is no current matrix-format check to loosen. If redesign introduces or encounters a matrix-specific parser elsewhere, replace it with format-independent semantic-link validation rather than requiring a table. The `>80`-character/heading body heuristic (`factory.py:114`) may be revised only with equivalent rejection tests for empty/incomplete artifacts. Retain machine-readable metadata and gate semantics; adjust renderer, validator, tests and author guidance together.
9. **Demonstrate no regression before merge.** Run old and redesigned templates through controller and CI tests, including legacy v1/v2 fixtures and both `check_job_artifacts.py` default and `--strict` modes; show expected existing advisory findings separately from introduced failures. Provide passing and intentionally failing fixtures for each invariant above, plus review sign-off on trace fidelity, citations and proportionate document length. Backward compatibility or a documented migration is required; no silent invalidation of existing jobs.
