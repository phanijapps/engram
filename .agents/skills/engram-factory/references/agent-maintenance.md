# Maintaining generated agents

## Authoring source

Edit references/shared.md for common rules, references/roles/ for role behavior,
references/reviews.md for specialist lenses, or agents/roles.json for names,
descriptions, disciplines and host permissions. Phase references own their detailed
protocols and artifact schemas. Do not edit generated host wrappers or Pi mirrors.
A role needs only its shared and role contracts plus explicitly relevant references.

## Regenerate and check

From the skill root, run `python3 scripts/generate_agents.py --repo-root REPO`.
It generates all four host dialects under agents/ and the repository Pi mirrors.
Explicit roots are supported for disposable fixtures and build integration.
Use `python3 scripts/generate_agents.py --check --repo-root REPO` to detect stale,
missing or manually changed generated outputs without repairing them. Python uses
only the standard library. Names, tools, permissions and output paths are validated;
symlinked sources/targets and foreign unmarked files are refused, not adopted.

Each output carries bundle-sha256 covering semantic roles.json metadata and all
references/**/*.md paths/bytes. Exact generated bytes are checked as well: copying
a digest marker onto a modified wrapper cannot make it valid. The digest identifies
canonical agent instructions, not authenticated owner authority or execution proof.

prepack invokes generation before copying skills into the launcher payload. The
launcher parity gate independently invokes --check, so synchronized stale authored,
payload and Pi files still fail. Payload copies are generated output too. Review
and validate the canonical edit, then regenerate; no background timer is required.

## Installation and active work

The installer copies the generated host wrapper and canonical skill references,
rewriting every skill-root pointer for the selected host/scope. Re-run the existing
installer at the intended project/user scope to refresh that installation; source
edits do not push updates into other repositories or machines automatically.

The existing installer ownership policy protects foreign names and symlinked
paths. It refreshes recognized managed files, including local edits to them.
Keep custom changes in canonical sources, not managed/generated installed copies.
Generation itself refuses unmarked conflicting files; it is not an adoption tool.

Serialize canonical edits, regeneration and installation refresh. Generation is
not one transaction across all files. It checks source/output identities and
refuses observed concurrent changes, but portable filesystem replacement is not
an authentication or arbitrary-writer compare-and-swap guarantee. A failed partial
generation must pass --check after reconciliation before packaging or dispatch.

Do not refresh an active job's instruction bundle silently. The supervisor records
the dispatched wrapper digest with invocation evidence. For installed contract
verification use `python3 scripts/generate_agents.py --digest --skill-root SKILL
--expected-digest SHA256`; digest mode reads canonical sources only and needs no
repository Pi mirrors. Mismatch blocks continuation until context is reconciled
at a safe checkpoint. Running agents are not hot-reloaded; an explicit resumed/new
invocation receives the appropriate packet. The local controller does not store or
authenticate this bundle pin, migrate jobs or grant new owner authority.
