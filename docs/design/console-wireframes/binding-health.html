Index-binding health

One line of facts about the code a partition indexes: repo, branch, indexed commit, freshness. Status only — no code-intelligence browsing, no writes.

Binding health line

the repo id is an engine key — bindings are per scope + repo, so supply the repo this partition actually indexes; your last-used value is remembered
line for 可视化研究 / mem-alpha:

mem-alpha: BOUND refs/heads/main · INDEXED 7a7ee95d · FRESHNESS-STATE: fresh

Corrected contract: the engine resolves exact repo ids — there is no “default” binding, so a hard-coded repo never resolves and every real partition would render an error. The operator supplies the id; the engine’s answer is the line. Stale freshness (ref-moved-past-indexed-commit) is a state, not an error — the branch simply moved past what was indexed, and the line says so.
